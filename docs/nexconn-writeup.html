OfferGraph

Multi-supplier offer intelligence for travel, with a real-time traveller ↔ travel-agent chat built on the Nexconn Chat SDK.

1. Why we built it

Travel inventory comes from many suppliers at once. The same tour or hotel appears several times under different names, prices and inclusions, and two listings that look alike can differ in things that matter: hotel pickup, skip-the-line access, meals, cancellation. Travellers end up comparing near-duplicates on their own. Travel agents want to help, but the advice usually happens on a separate phone call or WhatsApp thread, away from the listings being discussed.

We built OfferGraph to fix both parts. It cleans up and ranks the inventory, and it puts a live line to a human agent next to the results so a traveller can ask about a specific offer.

2. The problem it solves

  • Duplicate and look-alike listings: OfferGraph matches the same attraction or hotel across suppliers. Products with real differences stay separate as variants, so a "ticket only" listing is never merged with a "ticket + hotel pickup" one.
  • Ranking that ignores what the traveller asked for: a request in plain language (e.g. "Goa, 2 adults, free cancellation, hotel pickup") becomes must-haves and preferences. Every listing gets a pass, fail or "not stated" check, backed by the supplier's own data.
  • Advice happens outside the product: with the Nexconn chat, the traveller presses Ask agent on a listing. The listing arrives at the agent desk as a rich offer card in a 1:1 conversation, and the agent replies in real time.

Who it serves: travellers planning trips in India (live Viator inventory across 81 cities) and the B2B travel agents who advise them.

User flow

  • Traveller: opens Live India, searches a destination, presses Ask a travel agent or Ask agent on any listing. The SDK loads lazily (only when the chat opens) and connects with a token for a per-browser user id. Past messages load, and the shared offer card is sent.
  • Agent desk: open the site with ?agent. It connects as the shared og-agent user, switches to whichever traveller wrote most recently, loads that history, and replies. Both sides see live typing status.

Other parts of OfferGraph: Viator production API for live inventory, Upstash Redis for cache and rate limits, Gemini/Claude for turning requests into structured trip intent with a rule-based fallback, and a cross-supplier matching and ranking engine (src/engine/).

5. Security and limits

  • The App Secret exists only in Vercel environment variables. The browser receives just the public App Key and a token scoped to one user id.
  • Token issuance is rate-limited per caller (30 per hour) in Redis.
  • Scope: we use the Chat SDK only. We do not use Chat UI components or the Call SDK (no voice or video calls). The chat interface is our own React component built on the Chat SDK.
  • The agent desk is one shared agent identity. Routing across multiple agents is future work.
